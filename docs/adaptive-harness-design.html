The Adaptive
Harness.

A research platform for verifier-bounded recursive self-improvement, faithful to its founding claim: the harness around a model should itself be a model. Every routing rule, workflow, and reflex in the adaptive plane is authored by the executive at runtime — developer-written orchestration is zero. Boundaries are code, the model can never touch them, and the verifier — not the teacher — is the ceiling.

ADAPTIVE PLANE — model-decided FIXED PLANE — code-enforced
§0

Goal & Principles

Goal (Rev G; unchanged by Rev H): demonstrate verifier-bounded recursive self-improvement — measurable gains in the system's own orchestration policy and executive weights, learned from outcome signal without human labels, with the teacher as bootstrap rather than ceiling, inside an immutable boundary layer. Bounded is load-bearing and deliberately placed: the ceiling is the verifier, not the teacher. The loop may rewrite its policy and its weights; it may never rewrite its gate or its instruments. Every milestone in §12 is falsifiable, and the kill criterion is part of the goal, not a threat to it. Task throughput is a byproduct.

  • Mechanism in code, policy in the model. The kernel is a microkernel: small, immutable, boring. Everything interesting is a decision the executive makes through it.
  • Live judgment first; reflexes are earned. Every event wakes the executive. Standing rules exist only where the executive authored them — versioned, reason-coded, TTL'd so rigidity decays by default. Fast-pathing is a choice the model makes, never a default the developer made. (This also feeds the flywheel: a fast-pathed event produces no decision triple — Rev G's compilation default was quietly starving the training set.)
  • Zero developer orchestration. The adaptive plane ships with no developer-authored routing, workflows, or templates. Facts — prices, quota multipliers, lane capabilities — are given to the executive as context; rules are the executive's to write.
  • Subscriptions are agents, not endpoints. Codex and the GLM Coding Plan are consumed by driving their own supported tools headless — never by pointing raw harness code at plan endpoints.
  • Least-privilege context. The full task state lives only on the Mac. Every worker receives the minimum context its contract requires. This is simultaneously injection containment, IP hygiene, and cost control.
  • Cross-fleet verification. Two labs' models grade each other's work. No model reviews only itself on anything that matters.
  • Every decision is training data. The harness logs (state, decision, outcome) triples from day one. The cloud executive is a teacher on a clock.
  • Falsifiable or it doesn't count. Every capability claim binds to a number on the held-out suite. "It feels smarter" is not a result.
  • The gate never learns. Self-modification is confined to weights and routing policy. Kernel, capability registry, meters, and the eval suite sit outside the loop's write set — enforced by filesystem permissions, not discipline.
  • Goodhart is the adversary. Under outcome optimization, the primary failure mode is gaming the signal, not missing it. Seeded defects, operator-rotated held-out sets, and audit review are the experiment's control group, not overhead.
  • The benchmark suite is the customer. Contracts exist to feed and score the loop. This resolves the project's premortem: the research question is the captive workload.

Kernel K · FIXED

Python asyncio service on the M2 Max. SQLite for ledger, audit, and outcome logs. The kernel is deliberately dumb: it validates, meters, executes policy, and emits events. It holds no opinions about the task.

Invariants — enforced in code, non-negotiable

  • Every tool and adapter call carries a capability token scoped to (worker, tool, path-prefix, network). No token, no call.
  • No executive decision executes without passing JSON-schema validation. Invalid → decision_invalid event, bounded retry.
  • The executive cannot mint, widen, or transfer capabilities — including for itself. Kernel policy files are read-only to every model.
  • Budget and quota meters are checked before dispatch, not after. Hard stops beat apologetic overruns.
  • Every event, decision, and worker artifact is appended to the audit log before its effects apply. Replays are byte-deterministic.
  • Untrusted worker output is wrapped and tagged before it can enter any model context (§7).

The kernel never asks a model whether a permission check should pass. Capability decisions, budget stops, and audit writes are the fixed plane's whole reason to exist. If a future feature requires softening one of these, the feature is wrong.
§3

Executive E · ADAPTIVE

The executive is a reducer: (ledger, event) → decision. It never sees raw transcripts. It maintains a task ledger — goals, plan, constraints, open questions, budget state, recent outcomes — capped at ~3k tokens with self-compaction. One structured decision per wake, emitted as a strict tool call. Every event is a wake — the kernel forwards, it does not filter; only a reflex the executive itself authored (§6) may short-circuit one, and it expires unless re-affirmed.

Decision I/O

Server-enforced structured outputs (OpenAI strict schema) in Phase 1; grammar-constrained decoding via MLX/Outlines in Phase 3. The kernel re-validates regardless — defense in depth, not trust.

Reasoning-effort map

  • Routine dispatch / retry / verify decisions: Luna, minimal reasoning, cached prefix. Target < 2s, ~$0.002.
  • revise_plan / edit_policy / post-failure strategy: escalate to Sol at high reasoning. Seconds-to-minutes acceptable; these are rare by design.
  • Cache discipline: static system prompt + action schema sit before an explicit cache breakpoint, byte-identical across all tasks. 90% read discount; 1.25× write premium means the schema changes only at a version bump via the §10 ratchet — one deliberate re-warm, never tinkering.

Worker Fleets W · ADAPTIVE

All lanes sit behind one adapter interface: the kernel hands an adapter a contract, the adapter returns artifacts + a structured result. Nothing routes by developer default — the executive selects the lane per contract, with each lane's economics and opacity stated to it as facts.

WR — Raw lane (the faithful path)

  • Direct API calls — GLM-5.2 (Z.ai API or gateway), GPT-5.6 Sol/Terra/Luna, or the local model — inside a Chingis-owned minimal tool loop: bash, read_file, apply_patch, scoped to the contract worktree by capability tokens.
  • No inner harness: context assembly, tool sequencing, and in-lane retry limits are specified by the executive in the contract. What the post calls the dumb shell does not exist on this path at any layer.
  • Metered per token. Every step is transparent to the audit log — raw-lane trajectories are first-class flywheel data.

W1 — Codex fleet (optional packaged tool)

codex exec --json --sandbox workspace-write \
  --cd "$WORKTREE" "$(cat contract_prompt.md)"
  • Available when the executive judges a packaged inner loop worth its opacity — flat-rate under the ChatGPT plan, strong repo/diff workflow, fixed inner shell it cannot see into.
  • Expect safety-stack refusals on security-flavored tasks; worker_refused exists largely for this lane.

W2 — GLM fleet (optional packaged tool)

ANTHROPIC_BASE_URL=$ZAI_CODING_ENDPOINT \
ANTHROPIC_AUTH_TOKEN=$ZAI_KEY \
claude -p --output-format json --dangerously-skip-permissions=false \
  "$(cat contract_prompt.md)"
  • Claude Code (an officially supported coding-plan tool) run headless against the Z.ai endpoint — the defensible way to spend plan quota. Flat-rate; 1M-context inner model; fixed inner shell.
  • Quota is prompt-based with peak multipliers — supplied to the executive as context facts (§6).

W0 — Local fleet

  • MLX-served model on the M2 Max. Duties: cheap summarization, log triage, injection pre-screening, and shadow-executive scoring.
  • GPT-OSS 20B (~14GB) when the laptop is also a dev machine; Qwen3.6 35B-A3B (~20GB) when headless.

§6

Routing Policy ADAPTIVE · VERSIONED

Policy is data the executive writes. The routing file ships empty of routing content — day one, Chingis routes every contract by live judgment. The facts it needs (per-lane pricing, quota multipliers and peak windows, capability notes, refusal tendencies) are supplied as context, never as rules. When it notices a stable pattern, it writes itself a reflex.

# routing_policy.yaml — v1 ships EMPTY of rules.
# Every entry must carry author: executive + the decision that created it.
# Developer-authored routing content is a CI failure.

# Example — a reflex Chingis wrote for itself on day 9:
- match:  { task_type: coding_routine, window: "02:00-06:00 America/New_York" }
  action: { lane: W1 }
  author: executive
  reason_code: glm_peak_3x_quota
  created_by: d_00412
  ttl_days: 30      # expires unless re-affirmed by a fresh decision
  • Reflexes decay by default. TTL expiry purges any standing rule the executive stops re-affirming — rigidity exists only where the model currently chooses it. The kernel executes live reflexes deterministically between wakes; every other event wakes E.
  • The quota-arbitrage insight survives as knowledge, not law: the GLM peak-window facts sit in the executive's context. Whether they become a reflex is its call — and when Z.ai changes the multiplier, updating a fact beats hunting down a hard-coded rule.
  • Bandit evolution: per-(task-type, lane) outcome stats feed both live judgment and reflex-writing. M1 now measures whether the accreted reflex set beats reflex-free live judgment — whether Chingis's self-made rigidity earns its keep.
  • Racing is an economic decision: ~free in dollars on packaged lanes, metered on WR, always 2× in quota or tokens. The executive spends it when estimated difficulty and headroom justify it.
§7

Context Hygiene & Security

  • Ledger stays home. Full task state, decision history, and policy live only on the M2 Max. Neither lab's infrastructure ever holds the whole picture.
  • Least-privilege contracts. Workers get context_refs, not repositories; capability tokens, not shell freedom. A hijacked worker can damage exactly its worktree and nothing else.
  • Injection containment. All worker output re-enters the system as tagged, untrusted data. W0 pre-screens and summarizes before anything reaches the executive's ledger; the executive acts on summaries plus V1 facts, not raw text. Instructions found inside worker output are content, never commands.
  • Refusals are events, not failures. worker_refused reroutes per policy. The Sol safety stack tripping on crypto-adjacent material is expected background noise, handled in one hop.
  • Hard data boundary. Nothing employer-adjacent enters this system, on any fleet, ever. Personal projects only. This is a kernel-level allowlist on context sources, not a habit.
The novel attack surface of a model-orchestrated harness is orchestration hijack: injected text that persuades the executive, not a worker. The mitigations above exist for that path specifically. The kernel's schema validation + capability gates are the backstop when persuasion succeeds.

§10

The Improvement Loop

Formerly the economic endgame; since Rev F, this is the experiment. One cycle = act → log → consolidate → redeploy. Under Rev G, consolidation is outcome-driven: trajectories are scored by V1 ground truth and cross-fleet judgment, then consolidated via advantage-filtered behavior cloning and lightweight RL on the scored set. The teacher bootstraps and handles exceptions; it is no longer the ceiling. Every candidate is scored against the held-out suite before anything ships back into the live system.

  • Log schema: (ledger_snapshot, event, decision, reason_code, outcome, cost) — one row per executive wake, written by the kernel, replay-verifiable.
  • Teacher (bootstrap only): Luna for routine decisions, Sol for the hard ones — imitation gets the student to parity; outcome signal carries it past. Every metered dollar still buys training data.
  • Student: MLX QLoRA on a ≤14B target (or the 20B/35B via adapter), trained on decision traces filtered to good outcomes.
  • Redeploy gate: nothing ships back into the live system unless the consolidated candidate clears the §12 milestone criteria — shadow agreement, seeded-defect parity, zero capability-gate divergences. Regression means the cycle is discarded, not patched live.
  • Write set: a cycle may modify executive weights (LoRA adapters) and routing-policy YAML. Kernel code, capability registry, meters, and the eval suite are read-only to the loop at the filesystem level. The gate never learns.
  • Proposal ratchet: the loop may propose new action verbs, skills, tools, and eval tasks into a staging file. Operator batch-approves; schema version bumps; cache re-warms once. Growth is one-way, audited, and never self-authorized.
  • Continuation: the promoted local executive keeps logging; Sol keeps teaching the exceptions. Improvement without regression across cycles is the property under test — the one no rigid harness can have.
