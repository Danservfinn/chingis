## Order of operations

1. **Author the contracts.** 20 total, 10 seeded, 10 clean. Five are drafted; they span
   the five mechanisable defect classes and are written so the objective *forces* the
   generator to produce the shape the injection assumes. That constraint is what makes
   deterministic injection possible — respect it in the remaining fifteen.
2. **Fill the manifest.** Injection target file per seeded contract. Write-protected.
3. **Lock the pre-registration.** Read the underpowered-design section first; the options
   are only legitimate to choose now.
4. **Dry run.** `./run_b0.sh --dry-run` exercises worktrees, injection, prompt assembly,
   result parsing, and scoring without invoking a fleet or spending quota. Do this before
   Saturday, not on it.
5. **Run.** `./run_b0.sh` — 40 generations, 80 reviews. Resumable: anything already on
   disk is skipped, so an interrupted run costs nothing to continue.
6. **Score.** `./score_b0.py` → `results/report.md` and `results/scores.csv`.
7. **Adjudicate.** If the scorer queued ambiguous findings, resolve them before treating
   the verdict as final.

## The four arms

Each contract is generated **once per fleet**, and each artifact is reviewed by **both**:

```
         generated by W1 ──┬── reviewed by W1   (self)
                           └── reviewed by W2   (cross)
         generated by W2 ──┬── reviewed by W2   (self)
                           └── reviewed by W1   (cross)
```

That is the four arms the plan calls for, but it is a **paired** design rather than four
independent runs: self and cross see the identical artifact, so the contrast is not
confounded by generation variance. It also costs 40 generations instead of 80.

## What makes the number trustworthy

Every one of these is a way the experiment could quietly lie to you, and each has a
specific defense in the runner:

| Threat | Defense |
|---|---|
| Reviewer knows the artifact is seeded | Review prompt is built from rubric + objective + diff + V1 log. Nothing else. |
| Reviewer knows which fleet generated | Same — provenance never enters the prompt. |
| Rubric drifts between arms | One file, `verify/rubric/review_rubric.md`, protected path, byte-identical across arms. |
| Ground truth leaks into the diff | `inject.py` writes ground truth to the artifact dir, **outside** the worktree. |
| Injection silently doesn't land | Precondition regex; failure marks the pair `injection_failed` and the scorer **excludes it from the denominator and says so**. |
| Conspicuous seeded bugs | Defects are injected mechanically post-generation, never requested of the model. |
| Margin bought with false flags | False-flag rate measured on clean contracts, reported beside the catch rate, with a pre-registered guardrail. |
| Easy classes carry the pooled number | `deleted_failing_test` scored separately — it is the only class V1 cannot see. |
| Unparseable reviewer output read as "no findings" | Counted and reported; a nonzero count biases catch rates downward and the report says so. |
| Small-n overreach | Exact McNemar p-value and Wilson intervals in the report; the underpowered-design section is in the pre-registration, not discovered afterwards. |

## Layout

```
contracts/          20 contract JSONs (5 drafted, _TEMPLATE.json for the rest)
lib/arm.sh          the only place a fleet is invoked
run_b0.sh           generate -> inject -> V1 -> review
inject.py           deterministic post-generation defect injection
score_b0.py         -> results/report.md, results/scores.csv, results/adjudication.json
preflight.sh        what's missing and what it blocks
PREREGISTRATION.md  thresholds, locked before the run
artifacts/          diffs, V1 logs, prompts, ground truth  (gitignored)
results/            findings JSON + the report              (gitignored except *.md)
```

Deliverable: **one page, one number, one verdict.**
